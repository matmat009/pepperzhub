# PepperzHub — agent guide

Context for any AI coding agent (Claude Code, Codex, or other) picking up work in
this repo. Written against the actual state of the tree, not intentions.

---

## 1. Business context

**PepperzHub** sells peptide research compounds to the **Philippine market**.

- **Solo operator.** One person runs the whole thing. There is no staff, no
  support team, no roles/permissions system. "Admin" means the owner.
- **Guest checkout only.** There are no customer accounts and none are planned
  for now. Buyers are never asked to register. The only `users` row is the
  operator's own admin login.
- **Manual payment.** No payment gateway, no card processing. The buyer transfers
  to a bank account (shown with account details and a QR code), uploads a
  screenshot as proof, and the operator verifies it by hand before dispatch.
- **Currency is ₱ (PHP).** `formatPrice` pins this with `en-PH` and
  `currencyDisplay: 'narrowSymbol'` so it renders `₱` rather than `PHP`.
- **Local courier shipping at flat regional rates.** Not weight- or
  distance-calculated. The buyer picks a courier, then a region, and the rate is
  a fixed peso amount for that region.
- Storefront copy carries a research-use disclaimer: *"For laboratory research
  use only. Not for human consumption."* Keep it on any new storefront page.

## 2. Tech stack

Single **VPS monolith**. No separate API layer — Inertia is the transport, and
controllers return `Inertia::render` with props. Do not add REST/GraphQL
endpoints for the app's own screens.

| Layer | Choice |
|---|---|
| Backend | Laravel `^13.17`, PHP `^8.3` |
| Bridge | Inertia.js `^3.0` (`@inertiajs/vue3 ^3.0`) |
| Frontend | Vue 3 `^3.5` — **Composition API + `<script setup>`**, TypeScript `^5.2` |
| Styling | Tailwind `^4.1` — **CSS-first**, no `tailwind.config.js` |
| Components | shadcn-vue (on `reka-ui ^2.10`), icons from `@lucide/vue ^1.33` |
| Build | Vite `^8`, Wayfinder `@laravel/vite-plugin-wayfinder ^0.1.3` |
| Auth | Laravel Fortify + Passkeys (operator login only) |

**Tailwind v4 is CSS-first.** All theme tokens live in the `@theme` block in
`resources/css/app.css`. There is no config file to edit — adding a colour means
adding a `--sf-*` variable under `:root` and aliasing it as `--color-sf-*` inside
`@theme inline`.

## 3. Established conventions

These are load-bearing. Breaking them will fail tests or review.

### Wayfinder typed routes — never hardcode paths

Every link and form action uses a generated helper:

```ts
import { home } from '@/routes';
import { index as catalog, show } from '@/routes/storefront/products';
// <Link :href="show(product.slug)"> — not :href="`/products/${slug}`"
```

Generated output lives in `resources/js/routes/` and `resources/js/actions/`.
**Both directories are gitignored** — they are build artifacts, regenerated by
Vite. If you regenerate by hand, you **must** pass the form flag:

```bash
php artisan wayfinder:generate --with-form
```

Omitting `--with-form` strips the `.form` variants and breaks ~15 auth and
settings components with `Property 'form' does not exist`. The Vite plugin passes
`formVariants: true` already, so a normal `npm run build` is safe.

### Relational saves are id-preserving upserts

Never delete-all-then-reinsert a product's children. `Admin\ProductController`
has `syncVariants`, `syncTechnicalDetails` and `syncImages`
(`app/Http/Controllers/Admin/ProductController.php`), which update rows that
carry a known id, insert those that do not, then remove only what was dropped:

```php
$product->variants()->whereNotIn('id', $keptIds ?: [0])->delete();
```

An id belonging to a *different* product is inserted as new rather than hijacked.
This is enforced by **`tests/Feature/Admin/ProductRelationUpsertTest.php`** (5
tests). Follow the same shape for any new child relation.

### Two fonts, deliberately separate

| Surface | Family | Applied via |
|---|---|---|
| **Storefront** | **Lora** (serif) | `--font-display` / `--font-body`, both → Lora; `font-body` on `StorefrontLayout.vue` root |
| **Admin** | **Space Grotesk** | `--font-sans`, inherited from `<body class="font-sans">` |

This split is intentional — do not unify them. Loaded via `bunny()` in
`vite.config.ts`: Lora 400/500/600 + italic, Space Grotesk 400/500/600/700.
Storefront `.vue` files never name a family directly; they use `font-display`
(headings, wordmark, product names, prices, buttons) and inherit `font-body`
(everything else) so the family is swappable from one place.

### Route middleware

| Group | File | Middleware |
|---|---|---|
| Storefront | `routes/storefront.php` | **none** — fully public, no auth anywhere |
| Admin | `routes/web.php` | `auth`, `verified` |

`routes/storefront.php` is required from `web.php`. **The root route keeps the
bare name `home`**, not `storefront.home` — `AppSidebar.vue` and the four auth
layouts import `home` from the Wayfinder barrel, and renaming it breaks all five.
Everything else in that file takes the `storefront.` prefix.

### Shared price/stock utilities

`formatPrice`, `priceRange`, `totalStock`, `primaryPurity`, `formatDate` and the
`Product` / `ProductVariant` / `LabeledEntry` types all live in:

```
resources/js/pages/admin/products/all-products/types.ts
```

The storefront imports from there rather than duplicating. The path is odd for
shared code — it grew out of the admin screens — but it is the single source of
truth. Import it; do not copy it. If it ever moves, update both sides together.

## 4. Current build status

### Real, persisted

| Feature | Where | Notes |
|---|---|---|
| **Products** | `products` table, `Admin\ProductController` | Full CRUD. Status enum, featured flag, slug auto-generated from name |
| **Product variants** ("formats") | `product_variants` | Price and stock live **here, never on the product**. Kits carry `kit_inclusions` JSON |
| **Technical details** | `product_technical_details` | Purity and storage entries, typed + sorted |
| **Product images** | `product_images` + `public` disk | `public/storage` symlink exists |
| **Categories** | `categories`, `Admin\CategoryController` | Full CRUD. Deletion is **blocked** while products reference it — `CategoryDeletionTest` |
| **Storefront reads** | `Storefront\ProductController` | Home / Catalog / Product Detail. Filters `status = 'active'` only; drafts and archived 404 |
| **Auth** | Fortify + passkeys + 2FA | Operator login only |

Test suite: **61 passing, 235 assertions** (`php artisan test`). Coverage is
concentrated on the admin write paths and storefront visibility rules —
`ProductRelationUpsertTest`, `ProductDescriptionValidationTest`,
`CategoryDeletionTest`, `Storefront/ProductDescriptionTest`.

### UI-only — placeholder data, nothing persisted

There is **no orders, cart, customers or stock-movement schema**. These screens
render and validate, but write nothing:

| Page | File | Placeholder behaviour |
|---|---|---|
| **Cart** | `pages/storefront/Cart.vue` | State from `composables/useStorefrontCart.ts` — module-scoped `reactive`, **lost on reload**, never sent to the server |
| **Checkout** | `pages/storefront/Checkout.vue` | Full form + validation. Couriers/regions hardcoded (J&T: Luzon & Visayas ₱150, Mindanao Small ₱100, Mindanao Large ₱200). Payment hardcoded (GOtyme Bank, `0012 3456 7890`, PepperzzHub Trading). On submit it **routes to confirmation without saving** |
| **Order Confirmation** | `pages/storefront/OrderConfirmation.vue` | Fixed dummy order `PZH-00248`. Notify-Us links are `href="#"` |
| **Track Order** | `pages/storefront/TrackOrder.vue` | Exactly one lookup resolves: **`PZH-00231` + `09171234567`**, shown at the "Shipped" stage. Anything else hits the not-found state |
| **Admin Inventory** | `Admin\InventoryController` | ⚠️ **Zero database access.** Product list, stock counts and movement history are hardcoded arrays. `adjust()` flashes a toast and returns — it changes nothing |
| **Dashboard** | `pages/Dashboard.vue` | Starter-kit demo using `lib/dashboardDemoData` |

**Two traps in that table:**

1. **Inventory shows fake stock while real stock exists.** `product_variants.stock`
   is real and is what the storefront reads for availability. The admin Inventory
   screen ignores it entirely. Do not treat that screen as a source of truth, and
   do not wire new features to it before it is rebuilt.
2. **`resources/js/pages/admin/dashboard/`** (with `PendingPayments`,
   `RecentOrders`, `RevenueChart`, `StatsCards` partials) is **orphaned** — no
   route renders it. `/dashboard` renders `pages/Dashboard.vue` instead. Those
   partials are scaffolding for a dashboard that does not exist yet.

### Explicitly deferred — do not build unasked

- **Customer accounts / login** — guest checkout only, by design.
- **Payment gateway** — manual bank transfer + uploaded proof is the model.
- **Promo codes / discounts / vouchers** — no schema, no UI.
- **Inventory rebuild** — needs a `StockMovement` model and real reads off
  `product_variants.stock` before the screen means anything.
- **Orders schema** — the blocker for Cart, Checkout, Confirmation and Track
  Order becoming real. Build this first if asked to make checkout work.

## 5. Layout & routing map

Layouts resolve by page-component name in `resources/js/app.ts`:

```
storefront/*  → StorefrontLayout   (public nav + footer, no sidebar)
auth/Login, auth/Register → AuthSplitCardLayout
auth/*        → AuthLayout
settings/*    → [AppLayout, SettingsLayout]
default       → AppLayout          (admin sidebar shell)
```

`storefront/` is matched **first**, so no storefront page can pick up the admin
sidebar. Any new public page must be named `storefront/Something` to inherit
correctly.

| URL | Name | Component |
|---|---|---|
| `/` | `home` | `storefront/Home` |
| `/products` | `storefront.products.index` | `storefront/Catalog` |
| `/products/{slug}` | `storefront.products.show` | `storefront/Product` |
| `/cart` | `storefront.cart` | `storefront/Cart` |
| `/checkout` | `storefront.checkout` | `storefront/Checkout` |
| `/order-confirmation` | `storefront.confirmation` | `storefront/OrderConfirmation` |
| `/track` | `storefront.track` | `storefront/TrackOrder` |
| `/login` | `login` | Fortify |
| `/admin/products` | `admin.products.*` | admin CRUD |
| `/admin/products/categories` | `admin.products.categories.*` | |
| `/admin/products/inventory` | `admin.products.inventory.*` | placeholder |

**There is no route at `/admin`** — it is only a URL prefix. `/admin` returns 404
by design; the admin landing page is `/admin/products`.

## 6. Gotchas that have already cost time

- **`status` casing is asymmetric.** The DB column is a lowercase enum
  (`active` / `draft` / `archived`). Both controllers `ucfirst()` it into the
  payload, and the TS `ProductStatus` type is `'Active' | 'Draft' | 'Archived'`.
  Query with lowercase, render with capitalised.
- **Stale `public/hot` breaks everything silently.** If a Vite dev server dies
  without cleanup, Laravel keeps serving every asset from a dead URL and the app
  renders with no CSS or JS. Before concluding it is stale, note the dev server
  binds to **IPv6 `[::1]:5173`, not `127.0.0.1`** — probe
  `http://[::1]:5173/@vite/client` (a `200` means it is alive).
- **Vite config changes need a dev server restart.** Font changes in particular
  will not appear until `npm run dev` is restarted.
- **The seeded admin user is unverified.** `admin@gmail.com` has a null
  `email_verified_at`, and admin routes require `verified` — so login succeeds
  but bounces to `/email/verify`. Mark the user verified locally, or the admin is
  unreachable.
- **`design/` is excluded from ESLint** (`design/**` in `eslint.config.js`) — it
  ships a bundled prototype runtime that produced 700+ lint errors.

## 7. Design reference

`design/` is committed as the source of truth for the storefront and has its own
`design/README.md`. Read it before changing storefront visuals. Two things it
records that matter here:

- The export's `_ds/` design-system folder was **deleted deliberately** — it was
  a wrong-brand system (red accent, zero radius) that no artboard referenced.
- **Cart, Checkout, Order Confirmation and Track Order were implemented from
  structural reads, not verified line-by-line.** Diff those four against their
  `.dc.html` artboards before any pixel refinement.

Brand assets are extracted to `public/images/branding/`. The wordmark renders as
**live text**, never as an image — `pepperzhub-lockup.png` and
`pepperzhub-wordmark.png` are reference/fallback only and must not be used as the
live wordmark.

**Before calling any task done**, run `types:check`, `lint:check`,
`format:check`, `pint --test` and `php artisan test`. All five pass on `main`;
keep them passing.

## 9. Working agreements

- Match surrounding style: comments explain *why*, not *what*. Existing code is
  commented sparingly but substantively — follow that register.
- Do not touch `resources/js/pages/admin/`, `app/Http/Controllers/Admin/` or any
  existing migration when working on storefront tasks, and vice versa.
- New migrations only — never edit a migration that has already run.
- `resources/js/components/ui/` is shadcn-vue output; treat it as vendored and
  prefer composing over editing.
- When a screen needs data that has no schema yet, say so and build the UI
  against clearly-labelled placeholder data rather than inventing tables.
